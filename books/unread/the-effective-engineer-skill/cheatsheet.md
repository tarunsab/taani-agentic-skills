# Cheatsheet

## Start with the goal

1. What outcome matters now?
2. What is the scarce resource: time, attention, feedback, reliability, people, or information?
3. Which action has the greatest expected value per unit of that resource?
4. What evidence would make me stop, change scope, or invest more?

## Choose the next move

| Situation | First move |
| --- | --- |
| Too many tasks | Use the canonical backlog and compare the best next task with alternatives. |
| Important work keeps becoming urgent | Schedule Quadrant 2 prevention and protect maker time. |
| Many projects are half-done | Limit WIP and finish or explicitly pause work. |
| A design has a scary unknown | Prototype, benchmark, or solicit feedback on that risk first. |
| A release is slow or frightening | Shrink the batch; add tests, canary, metrics, and rollback. |
| A metric improves but behavior does not | Check definition, denominator, cohort, tail, and event integrity. |
| Scope is growing | Re-state the specific goal and ask whether each task is required for the next milestone. |
| A system needs constant manual care | Simplify first, then automate recurring mechanics. |
| One person is always paged | Raise the bus factor with rotation, documentation, review, and teaching. |

## Fast diagnostic rules

- **Leverage:** Can the work take less time, produce more output, or move to a higher-leverage activity?
- **Learning:** Am I getting challenge, feedback, capable peers, openness, training, and sustainable pace?
- **Iteration:** Where is the largest wait between idea, change, evidence, and decision?
- **Metrics:** What behavior does this target reward, and what guardrail catches gaming or harm?
- **Validation:** What is the cheapest credible test that could change the decision?
- **Estimation:** Is this an honest forecast or a target disguised as a forecast?
- **Quality:** Is the proposed ritual preventing a recurring risk, or only increasing ceremony?
- **Operations:** Does retrying this action duplicate effects, and can recovery be practiced?
- **Team:** Does the system still work if its most knowledgeable person is unavailable?

## Stop signs

- “Almost done” without a measurable milestone.
- A rewrite that bundles unrelated cleanup and new features.
- Averages that hide a bad tail.
- A big launch whose demand or architecture has not been tested.
- A faster local tool while approval or priority is the real bottleneck.
- A single owner for a critical service.
- A post-mortem that seeks blame instead of evidence and changed practice.

## One-minute review

State the current goal, next action, expected leverage, evidence to collect, and review time. After the review, either make the next small change, run the cheapest useful experiment, or remove the task from the active queue.
