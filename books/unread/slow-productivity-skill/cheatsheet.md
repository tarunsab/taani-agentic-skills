# Cheatsheet

## Core Decision Rules

| If you notice… | Do this | Because… |
|---|---|---|
| Messages and meetings are the main evidence of work | Identify the durable core output | Visibility is not value; this is pseudo-productivity |
| A new project has no honest calendar space | Decline it or displace another commitment | “Busy” is weak; time evidence is defensible |
| The list is growing faster than work finishes | Reduce active work before optimizing tools | Overhead tax compounds with each open commitment |
| Work is pushed from every direction | Use a holding tank and active list capped at 3 | Pull prevents capacity from being overrun |
| A request is vague | Ask for missing details, current queue count, and an estimated completion date | Friction clarifies ownership and reduces prodding |
| A project generates endless small requests | Prefer the lower task-footprint option or delegate | It may be a task engine |
| An important project keeps slipping | Return without penance; ask “What’s next?” | Natural pace is not a license for burnout |
| A workday feels permanently frantic | Protect at least half the day from meetings and cut the task list 25–50% | Cognitive time is routinely overestimated |

## Capacity Defaults

| Scale | Default |
|---|---|
| Missions | Prefer 1–3; treat 5+ as a warning to simplify |
| Active projects | At most 3 in simulated pull |
| Major daily target | 1 project |
| Project estimate | Double the first reasonable estimate |
| Daily task list | Remove roughly 25–50% |
| Meetings/calls | No more than half of a day; pair each appointment with equal protected time |
| Work cycles | 6–8 focused weeks, then 2 cooldown weeks |

## Incoming-Work Flow

1. Record the request in the holding tank.
2. Send an acknowledgment: request missing information; state the number of existing commitments; give a dated/period estimate.
3. Pull only when an active slot opens.
4. Update the source if the estimate changes.
5. Clean weekly: prioritize deadlines, release languishing or obsolete work transparently.

## Quality Gate

- What one or two outputs actually determine impact?
- What excellent work in this field—and outside it—would raise my standard?
- Does this choice buy quality, or merely add visible activity?
- Is the bet bounded: enough pressure to focus, enough recovery to remain sustainable?
- Am I seeking “good enough to advance” or hiding perfectionism behind more time?

## Smells

`working late to finish coordination` · `saying no only after panic` · `a full calendar with little core output` · `a short project with many requesters` · `a familiar home office full of chore cues` · `quitting before demand is repeatable` · `quality work postponed for low-value responsiveness`
